# 開発者向けの情報

使う人向けの説明は [README](../README.md) を参照。

## 画面設計の方針

画面は左が動画の一覧（サイドバー）、中央が動画と再生バー、右が人の一覧（インスペクタ）。macOS 26 の Liquid Glass と標準部品で作り、Apple 標準アプリ（プレビュー・QuickTime Player）と HIG を参考にしている。説明は常に見える短い文として操作のすぐそばに置き、ツールチップだけに頼らない。ボタンはカプセル形で、ガラスはツールバーと動画の上に浮かぶ部品だけに使う。

色の意味は 1 つずつ：アクセント色（青）＝モザイクをかける、橙＝確かめてほしいこと、赤＝エラー。文字は黒・灰色だけにして、状態の色はアイコンに付ける。

## 書き出しの画質（詳細）

- 元の動画のコーデックを引き継ぐ：H.264 → H.264、HEVC → HEVC（10bit は Main10）、ProRes 422/HQ/LT/Proxy/4444 → 同じ ProRes
- 10bit の H.264（XAVC S/XAVC-L/XAVC-I などの High 10・High 4:2:2）は、H.264 の 10bit をハードウェアで書けないため HEVC Main10 で書き出す（10bit は保たれるが、**4:2:2 は 4:2:0 になる**）
- AV1・MJPEG・MPEG-2 など、上以外のコーデックは HEVC で書き出す
- H.264/HEVC のビットレートは元の 1.3 倍（最低 2Mbps）。元のビットレートはファイルサイズ÷長さで上限をかけて推定する（MPEG-PS で値が大きく出すぎるため）。色空間（primaries/transfer/matrix）・回転情報も引き継ぐ
- モザイクのないフレームはデコードしたまま再エンコードする。音声は再エンコードせずにそのままコピー
- 出力は `.mov` / `.mp4` / `.m4v`

## 対応している動画形式（確認結果）

macOS（AVFoundation）で読める形式はそのまま開ける。2026-11-12 に合成したテスト素材で確認した結果：

| 開ける | 開けない（変換が必要） |
|---|---|
| MOV / MP4 / M4V / 3GP、MPEG-TS（.ts）、MPEG-2（.mpg） | MKV、WebM（VP9）、WMV、FLV |
| H.264（8bit・10bit・4:2:2）、HEVC（8bit・10bit・4:2:2）、ProRes、AV1（MP4）、MJPEG（AVI・MOV） | AVI に入った MPEG-4 Part 2（MP4 に入っていれば開ける） |
| **MXF（Sony FX6/FX3 などの XAVC）**：ffmpeg があれば自動で MOV に入れ替えて開く（下） | |

- **MXF の自動入れ替え**：AVFoundation が開けないファイルは、`ffmpeg`（`brew install ffmpeg`）で映像と全音声トラックを**再エンコードせずに** MOV へ入れ替えてから読む。一時ファイルは macOS の一時フォルダに作り、一覧から取り除く・アプリ終了・次回起動時に消す。タイムコードなどのメタデータは引き継がない。ffmpeg がなければ「開けません」と理由を表示する
- 確認したのは ffmpeg で作った XAVC-L/XAVC-I 相当の合成 MXF（4ch モノラル音声）。**実機の FX6 の MXF・HLG の色情報の引き継ぎは未確認**
- 開けない形式は、一覧に「開けません」と出る（MP4・MOV への変換を案内）

## 仕組み

1. 顔を検出する。画面全体は毎フレーム、小さい顔のための n×n タイルは 0.1 秒ごと（人物方式）。重複はまとめる
2. フレーム間で顔をつないで「トラック」にする（重なり、速い動きは中心距離で補う）
3. **顔が見つからなくなったら頭を追いかける**：横を向いた・速く動いてブレた等で顔検出が外れたら、前のフレームの顔の 1.6 倍の範囲（髪・耳・首を含む）を Vision の物体追跡で追う（最長 5 秒、追跡の信頼度が下がったら止める）。トラックが途切れないので、モザイクも外れず、人も分かれにくい
4. トラックを人にまとめる。服や髪を含む広めの切り抜きの特徴量（Vision の FeaturePrint）の距離が 0.45 以下ならまとめる。**同じフレームに同時に映るトラックは別人として扱う**。0.6 以下の人どうしは「同じ人かも」として示す
5. モザイクの範囲（選んだ人ごと）：
   - トラックの中で検出のないフレームは前後の位置から補間。追跡で補った箱は 1.25 倍に広げる
   - 同じ人の2つのトラックの間が 2 秒以内なら、その間も補間した位置（1.3 倍）にモザイクを続ける
   - 顔が現れる前と消えた後も、既定 1 秒はその位置にモザイクを残す

## 画面の文字の仕組み

1. 全フレームをデコードし、160px 幅に縮めた白黒の画像で前に読み取ったフレームと比べる。変わっていなければ読み取りを省き、前の結果を使う（ただし 1 秒おきには読み直す。数字 1 文字の変化のように縮めた画像では分からない変化のため。そこで初めて見つかった行は、前に読み取った直後のフレームから出ていたものとして隠す）。変わっていれば最短 0.1 秒おきに Vision の文字認識（`VNRecognizeTextRequest`、accurate、日本語と英語、言語補正なし）で行を読む。1 フレームあたり 150〜330ms（886×1920）で、並列にしても速くならなかった（2026-11-13 計測）。`.fast` は日本語を読めない
2. 止まっていた場面が動き出すときは、動き出す直前のフレームにも前の結果を置き、止まっていた間の位置を固定する
3. 読み取ったフレームどうしで行をつなぎ「トラック」にする（文字の近さ＝編集距離 0.6 以上、位置、高さで対応づけ）。2 回続けて読み落としてもつなぐ。数えるのはフレーム数ではなく読み取った回数（止まっている間は読み取らないため。動き出す直前に置き直す前の結果は数えない）
4. 読み取ったフレームの間は位置を補間する。スクロールは加速・減速するので、隠す部分の箱（行の箱ではなく）を動きの方向に、動いた距離の最大 40%（中間で最大）広げる。最初と最後は 0.35 秒（読み取りの間隔 0.1 秒＋フェードの分 0.25 秒）前後にも隠す（その間に出てきた・消えた・フェードした行。動きの延長は 1.5 区間分まで）。時間はフレーム数ではなく各フレームの時刻で測る（可変フレームレートの動画のため）
5. 行ごとに、読み違いを含むすべての読み方を正規表現で調べ、個人情報の部分を行の箱に対する割合で覚える。どこかのフレームで正しく読めていれば、その行のトラック全体で隠す。部分の箱が取れないときは、見つけたものを捨てずに行全体を隠す。照合は NFKC で全角・半角をそろえる。隠す範囲は行の高さに対して左右 35%・上下 30% 広げる
   - 住所は、見つかった所から行の終わりまで隠し、すぐ下の行（左端がそろい、行の間が行の高さの 0.8 倍未満、高さが 0.7〜1.4 倍。両方が読めたフレームを優先し、なければ片方が読めたフレームで、もう片方を補間した位置と比べる）も行全体を隠す。行の終わりまで続くメールアドレス・URL も同じ判定で、すぐ下の行の始めの英数字・記号を隠すテスト動画では、吹き出しの中の行間が約 0.27 倍、吹き出しどうしが 1.5 倍以上だった
   - 隠す言葉は、すぐ後の空白を飛ばして漢字・カタカナ 4 文字まで（名字に続く名前）も隠す。ひらがなで止める
   - 人の名前（`Names.swift`）：macOS の NaturalLanguage は日本語の人名を判定できない（`NLTagger` の `nameType` が日本語では使えない。2026-11-13 確認）ため、よくある名字の一覧で探す。名字の後に敬称か「です」、空白か直接の漢字 1〜3 文字（名前。「高橋健太郎様」のように漢字の敬称が続いてもよい）、カタカナ 2〜5 文字、空白の後のひらがな 2〜5 文字（行や単語の終わりまで）、敬称の前のかな（「山田さくらさん」）が続くとき、または行が名字だけのときだけ隠す。1 文字の名字（森・林など）は、敬称か空白をはさんだ名前が続くときだけ。名字の直前が漢字なら単語の途中とみなし、敬称が続くときだけ、直前の漢字 2 文字までも含めて隠す（「担当田中様」→「担当田中」、一覧にない「桑原さん」→「桑原」。「です」は社名にも続くので数えない）。かなの名前は字種をそろえる（「山田サクラです」のカタカナはひらがなで止まる）。空白なしのひらがなは、敬称が続くか行がそれだけのとき（「山田さくら」）だけ
6. 書き出しと「モザイクあり」の表示には、顔の箱（`FrameFaces.mosaic`、広さ pad を足す）とは別の欄（`FrameFaces.exact`、そのまま描く）で渡す
7. 読めなかった間をつなぐ：隠す行のトラックが終わったあと、3 秒以内（「すべて隠す」では 6 秒）に近い位置（中心の差が行の高さの 1.5 倍未満、高さ 0.6〜1.6 倍）で似た文字（編集距離 0.6 以上。「すべて隠す」では文字を問わない）の行が始まれば、その行を続きとみなし、その間も位置を補間して隠す。続きでつながった行どうしは、隠す部分を前後両方向に合わせる（読み違えた行が先でも後でも、片方だけで見つかった部分も、つながった全部の行で隠す）
8. アプリでは、隠す範囲の計算（`ScreenText.mask`）を裏で行い、古い計算は取り消す。選択を変えてから計算が終わるまでは書き出せない。書き出し待ちの間に選択が変わったときは、書き出す直前に計算し直し、書き出しの記録には実際に使った選択を残す（古い範囲で書き出して「書き出し済み」と出ないため）

## 速さについて

顔の検索で時間がかかるのは Vision の顔検出の呼び出しで、1 回あたりの時間はほぼ一定（1080p で約 5〜8ms）。並列に投げても、Neural Engine・GPU・CPU に振り分けても速くならなかった（2026-11-12 計測）。そのため、呼び出しの回数を減らしている：

- 画面全体は毎フレーム、タイル（4×4 なら 16 回）は 0.1 秒ごとだけ探す。間のフレームはトラックの補間で埋める。毎フレーム探した場合と、テスト動画の全フレームで結果が一致することを確認済み
- 1 フレーム内の領域と、8 フレーム分をまとめて同時に処理し、切り抜きなどの CPU 処理を検出の待ち時間と重ねる

## 制限（詳細）

- 人の検出は**顔だけ**。後ろ姿・服などは対象外。文字は `analyzeText`（画面録画と、画面をカメラで撮った動画で確認）
- 画面の文字で、とても速いスクロール（読み取りの間に行の高さの数倍以上動く）では、同じ文字の行が続く画面で別の行とつながり、外れることがある。2 行以上に折り返したメールアドレス・URL の続き、読み方によって行の幅が大きく変わる場合の部分の位置もずれることがある
- カメラで撮った画面（1080p、手持ち）は、30 秒あたり約 40〜80 秒かかる（画面が常に動くので毎回読み取る）。ブレ・反射・指で読めない時間が 6 秒を超えた文字や、端にぽつんとある小さい文字（時刻など）は残ることがある（2026-11-13、市販のレビュー動画の一部で確認）
- 横顔・強いブレは頭の追跡で補うが、最初から横顔のまま登場した顔や、マスク、小さい顔（約 20px 未満）は取りこぼすことがある。「確認してほしい箇所」は数の減少で見つけるので、**ずっと見落とし続けた顔は出てこない**
- 同じ人が2人以上に分かれて一覧に出ることがある（服や照明が変わる・長く画面から消える等）。「同じ人かも」が付かない場合もあるので、サムネイルを見て全部チェックする
- 「同じ人かも」・自動でまとめる基準は合成テスト素材で決めた値（同じ人の正面と横向き 0.35、別人 0.85 以上）。実際の動画では、似た服装の別人がまとまる・ヒントが付くことがある
- Vision には顔の本人確認の API がないため、登録写真との照合は汎用の画像特徴量で行う。架空人物のテストでは、動画に映る人の写真 12 枚中 10 枚で本人が候補になり、映っていない人の写真 7 枚中 2 枚で別人が候補になった。**候補はあくまで初期チェック**
- 左右反転の回転情報を持つ動画はエラーで止まる
- 動画をまたいだ「似ている人」の基準も合成素材で決めた値。実際の動画どうしでは距離が大きく出て、ヒントが付かないことがある
- 開発中にターミナルから `open -g build/モザイぷーん.app` のように裏で起動すると、ウインドウが出ない（SwiftUI の仕様）。動画を渡して起動するときは `open -a build/モザイぷーん.app <動画>...` を使う
- 処理時間の目安（1080p30、高精度、M3 Max）：顔の検索は動画の長さの約 0.6〜0.8 倍（10 秒で約 7 秒、64 秒で約 37 秒）。書き出しは H.264 で 10 秒の動画が約 2 秒
- **公開前に、書き出し結果を必ず通しで目で確認する**

## 配布用のビルドと公開

`scripts/build-app.sh --zip` で、Apple シリコンと Intel の両方で動くアプリ（ad-hoc 署名）と `build/Mozaipoon-<版>.zip` ができる。版は `scripts/build-app.sh` の `VERSION`。zip は拡張属性を含めずに作る。

公開は GitHub Actions（`.github/workflows/release.yml`）で行う。リリースの作成者を個人のアカウントではなく `github-actions[bot]` にするため、手元から `gh release create` しない。

1. `scripts/build-app.sh` の `VERSION` を上げ、`.github/release-notes/v<版>.md` にリリースノートを書いて push する
2. `git tag v<版> && git push origin v<版>` でタグを push すると、macOS のランナーでビルドし、zip と SHA-256 を付けてリリースを作る

Developer ID の署名と公証をしていないため、ダウンロードした人の Mac では初回に Gatekeeper で止まる（README に開き方を書いている）。止まらないようにするには、Apple Developer Program に登録して Developer ID で署名し、`notarytool` で公証する必要がある。

## アイコン

アイコンの元データは `assets/icon/AppIcon.svg`。変えたら `node scripts/render-icon.mjs assets/icon/AppIcon.svg assets/icon/AppIcon.png`（Playwright と Google Chrome が必要）で 1024px の PNG にし、`scripts/build-app.sh` を実行すると各サイズのアイコン（AppIcon.icns）が作られてアプリに入る。

## AI コーディングツールで開発するとき

ツールに読ませたファイルやコマンドの出力は、そのツールのサーバーに送られることがある。実際の人が映った動画はアプリか自分のターミナルで処理し、ツールの作業フォルダに置かない。ツールには `testdata/` のダミー素材だけを使わせる。

## テスト（ダミー素材）

テスト素材はリポジトリに含めていない（開発者の手元の `testdata/` に置く。`.gitignore` 済み）。人物はすべて AI で生成した架空の人物、または scikit-image 同梱の NASA の写真（パブリックドメイン）。画面の文字のテスト動画 `screen.mov` だけは、`node scripts/make-screen-sample.mjs` で作れる（Playwright と Google Chrome、ffmpeg が必要）。

```sh
B=.build/release/wipe-mosaic
# 人名・番号・URL・橋渡し・住所の続き行の規則（見つけて直した不具合ごとの例。動画不要。Command Line Tools には XCTest と swift-testing のマクロがないため CLI で実行）
$B selfcheck                                                    # selfcheck: all passed
# people.mov: 4人（P2 は全編、P1 は 0〜4秒と 5〜10秒で向きが変わる、P3 は小さく 2〜7秒、P4 は 6秒から）
# motion.mov: P1 が速く動き、3.0〜4.2秒・6.0〜6.7秒は顔がぼかしで見つからない（横顔の代わり）。P2 は静止
# split.mov: P1 が 0〜2.5秒（正面）・4〜5.5秒（照明違い）・7秒〜（横向き）で別の場所に出る。P5 は別人
$B people testdata/people.mov -o testdata/out/people
$B run testdata/people.mov testdata/out/p.mov --people 2 --report testdata/out/p.csv --overwrite
# ワイプ方式の回帰: t<5s はモザイク2・本人1、t>=5s はモザイク3・本人1
$B run testdata/sample.mov testdata/out/result.mov --wipe 1480,640,400,400 --report testdata/out/report.csv --overwrite
awk -F, 'NR>1{e=($1>=5.0)?3:2; if($2==e&&$3==1)ok++; n++} END{print "match " ok "/" n}' testdata/out/report.csv
# 画面の文字: screen.mov は架空の個人情報を表示したチャット画面（0〜2秒静止、2〜5秒スクロール、5.5〜7.8秒通知）
# node scripts/make-screen-sample.mjs で作る（scripts/screen-sample/phone.html から）
$B text testdata/screen.mov --words 山田,佐藤,鈴木 --list        # hidden 13 lines
$B run testdata/screen.mov testdata/out/s.mov --screen-text --words 山田,佐藤,鈴木 --report testdata/out/s.csv --overwrite
awk -F, 'NR>1{if($5>0)ok++; n++} END{print "frames with text boxes " ok "/" n}' testdata/out/s.csv   # 270/270
```
